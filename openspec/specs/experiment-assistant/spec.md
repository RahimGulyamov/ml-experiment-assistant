# Спецификация: анализ ML-экспериментов

## Purpose
Помочь ML-инженеру сравнить выполненные запуски и сформировать проверяемую
гипотезу следующего эксперимента, сохранив происхождение численных выводов.

## Requirements

### Requirement: Validated import
Система SHALL принимать JSON и CSV до 2 MiB, не более 200 запусков и 200 точек
истории на запуск. ID SHALL быть уникальными; числа SHALL быть конечными.
Невалидный импорт SHALL сохранять предыдущий набор и показывать причину.

#### Scenario: Duplicate run
- WHEN файл содержит два одинаковых ID
- THEN импорт отклоняется с сообщением о дубликате.

### Requirement: Comparable evidence
Система SHALL ранжировать только запуски одной группы experiment/dataset/split.
Направление метрики SHALL задаваться явно. Запуск без выбранной метрики SHALL
исключаться с предупреждением. Относительное изменение при нулевом baseline
SHALL возвращаться как null, а не Infinity. Все числа вычисляются кодом.

#### Scenario: Minimize loss
- GIVEN loss 0.4 и 0.2, direction=min
- WHEN вызывается compare_runs
- THEN победитель — запуск с 0.2, абсолютное улучшение 0.2.

### Requirement: Real MCP
Система SHALL использовать официальный MCP SDK и выполнять initialize,
tools/list, tools/call. `/api/mcp` SHALL предоставлять Streamable HTTP для учебного
набора. Агент SHALL вызывать инструменты через MCP client, не напрямую.
Загруженный набор SHALL быть изолирован в контексте одного запроса.

#### Scenario: Public SDK comparison
- WHEN внешний SDK-клиент подключается к публичному `/api/mcp`
- THEN выполняются initialize, tools/list и tools/call
- AND сравнение run-001 и run-005 по accuracy/max возвращает run-005.

#### Scenario: Concurrent dataset isolation
- GIVEN два запроса с разными наборами запусков
- WHEN каждый клиент вызывает list_runs
- THEN каждый получает только данные своего запроса.

### Requirement: LLM orchestration
При наличии ключа LLM SHALL выбирать разрешённые инструменты и формировать
ответ по их результатам. До первого tool call модель SHALL получить
tool_choice=required. Лимит — 6 раундов и 12 вызовов инструментов.
Ответ SHALL содержать ID, оговорки об отсутствии причинного доказательства
и гипотезу следующего шага, когда вопрос её требует.
Ошибки провайдера SHALL показываться без токенов и без подмены ответа демо-текстом.

#### Scenario: Model-selected comparison
- GIVEN ключ и модель с поддержкой tool calling
- WHEN пользователь спрашивает о сравнении запусков
- THEN модель получает tool_choice=required на первом раунде
- AND MCP выполняет выбранный разрешённый инструмент
- AND результат инструмента передаётся модели для финального объяснения.

#### Scenario: Provider rejects key
- WHEN провайдер возвращает HTTP 401
- THEN пользователь видит сообщение об отказе ключа
- AND тело ответа провайдера и ключ не появляются в сообщении.

#### Scenario: Tool loop limit
- WHEN модель пытается вызвать тринадцатый инструмент
- THEN анализ завершается сообщением о лимите без выполнения этого вызова.

### Requirement: Honest offline mode
Без ключа SHALL быть доступен расчётный обзор через MCP с отметкой «Без LLM».
Свободный вопрос SHALL требовать подключения модели. UI SHALL не называть
расчётный шаблон ответом нейросети.

#### Scenario: Calculation without credentials
- WHEN пользователь выбирает обзор без ключа
- THEN сервер вызывает инструменты через MCP
- AND результат содержит mode=overview, а UI показывает «Без LLM».

#### Scenario: Free question without credentials
- WHEN пользователь отправляет свободный вопрос без ключа
- THEN интерфейс предлагает подключить модель и не выдаёт шаблон за LLM-ответ.

### Requirement: Safe boundaries
Ключ SHALL не попадать в localStorage, отчёты, логи и исходники.
Разрешённые провайдеры SHALL определяться сервером, не произвольным URL из формы.
LLM SHALL не получать файловую систему, shell, секреты или право менять данные.
Интерфейс SHALL выводить ответ как текст, не исполнять HTML из импортов/LLM.

#### Scenario: Arbitrary provider denied
- WHEN запрос содержит URL внутреннего сервиса вместо разрешённого провайдера
- THEN схема отклоняет запрос до сетевого обращения.

#### Scenario: Untrusted HTML and report
- GIVEN импорт или ответ модели содержит HTML-разметку
- WHEN интерфейс показывает этот текст
- THEN разметка не исполняется
- AND экспорт отчёта не содержит API-ключа или заголовка Authorization.

### Requirement: Delivery
Репозиторий SHALL содержать README, план, OpenSpec, тесты, CI, примеры файлов,
инструкции самостоятельного развёртывания и интерактивную HTML-презентацию.
Проверки реального LLM и опубликованных ресурсов SHALL отмечаться отдельно
от тестов с подставным провайдером.

#### Scenario: Reproducible submission
- WHEN репозиторий клонирован в чистое окружение с поддерживаемой Node.js
- THEN npm ci, npm run check и npm run build завершаются успешно
- AND строгая проверка OpenSpec завершается без ошибок.

#### Scenario: No real model available
- WHEN на момент проверки нет рабочего API-ключа
- THEN отчёт явно отмечает реальную LLM-проверку как невыполненную
- AND успех тестового провайдера не считается её заменой.
