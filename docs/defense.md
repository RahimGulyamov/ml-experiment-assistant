# Сценарий защиты: 8–9 минут

До выступления: открыть сервис, `/developer`, `/presentation` и локальный
AI-клиент с MCP. Проверить доступ к модели и заранее выполнить контрольный запрос.
Для веб-чата нужен отдельный API-ключ; локальная подписка не подставляется в это поле.
На записи не показывать ключи, корпоративные данные и настройки доступа.

## Ход

- **0:00–0:45.** Задача ML-разработчика: сравнить запуски и объяснить ограничения,
  затем перейти к проверяемому следующему эксперименту.
- **0:45–1:30.** Два маршрута: Web → LLM API → HTTP MCP и подготовка файла →
  локальный AI-клиент → stdio MCP. Объяснить, какой показывается сейчас.
- **1:30–3:00.** `/developer`, искусственный Training. У A есть шаг 300, у B —
  только 200. Сравнение обеих метрик использует полный общий шаг 200:
  quality .75 → .79, loss .50 → .44. Экспорт не подтверждает завершение обучения.
- **3:00–4:30.** В локальном клиенте попросить сравнение через MCP и анализ
  ab-demo. Раскрыть реальные tool calls. A/B: engagement +2%, но negative_feedback
  +20%, меньше лучше, ДИ целиком в зоне ухудшения. Отчёт промежуточный,
  множественные сравнения не описаны. Автоматической рекомендации раскатки нет.
- **4:30–5:30.** Основной интерфейс. Открыть реальные Iris-замеры и показать
  равные accuracy=1.0. Тридцать validation-примеров не доказывают равенство моделей.
  Если веб-ключа нет, назвать этот показ расчётным режимом.
- **5:30–6:30.** OpenSpec, ожидаемые значения в тестах, интеграция настоящим SDK.
  Показать подтверждение реальной LLM в verification-real-llm.json и границы проверки.
- **6:30–7:30.** Ревью: общий шаг, нулевой baseline, несовместимые протоколы,
  экспорт только выбранных данных. Показать один соответствующий тест.
- **7:30–8:30.** Что требуется для команды: подтверждённые read-only API Training
  и A/B внутри компании, SSO, разграничение прав и аудит. Ответы на вопросы.

Локальная реальная LLM проверена, но это не подтверждает веб Chat Completions API
или интерфейс корпоративного launcher. Если преподаватель требует именно живую
цепочку веб-чата, перед защитой нужен ключ и отдельная проверка этой цепочки.
Наличие курса, согласование темы и обязательный воркшоп нельзя выполнить кодом.

## Возможные вопросы

**Зачем MCP, если можно вызвать функцию?**
Стандартные discovery, схемы и transport позволяют подключить тот же анализ к
другим клиентам. В проекте есть настоящий SDK, HTTP и stdio; формулы остаются в коде.

**Где AI-логика?**
Модель выбирает инструменты по вопросу, связывает их результаты, объясняет
компромиссы и предлагает гипотезу. Числа вычисляет инструмент. Без модели есть
отдельный ограниченный обзор, который не называется AI-ответом.

**Что именно проверено с реальной моделью?**
Авторизованный локальный Codex вызвал list_workspace_sources,
compare_training_exports и analyze_ab_result. Ответ содержит правильные шаг,
разницу и guardrail. Использован default клиента; точный model ID журнал событий
не сообщил. Это одна контрольная проверка, не широкая оценка качества LLM.

**MCP подключён к корпоративным платформам напрямую?**
Пока поддержан формат скалярной выгрузки и портативный A/B-отчёт. Инструменты читают
явно выбранный локальный workspace. Сетевой коннектор требует официального контракта
и прав внутри компании; публичные fixtures полностью искусственные.

**Почему нельзя сравнить последние точки или максимумы?**
Они могут относиться к разным шагам обучения. Разница тогда смешивает эффект
изменения модели с эффектом продолжительности обучения. Нужны общий шаг и одинаковый
протокол. Даже после этого один seed не доказывает значимость.

**Откуда доверительные интервалы?**
Из входного A/B-отчёта с явными единицами. Система не вычисляет их из средних и
не подтверждает метод исходного сервиса. При CI через ноль сигнал неопределённый.
Улучшение primary не отменяет ухудшение guardrail.

**Как защищены данные?**
В developer-странице нет загрузки на сервер. В MCP нет произвольных файловых путей
и инструментов записи. Передача модели всё равно подчиняется политике AI-клиента.
Для корпоративных данных нужна разрешённая локальная/внутренняя копия и модель.

**За что отвечает автор?**
AI-агент реализовал код, тесты и документы. Автор понимает сценарий и архитектуру,
проверяет критерии, проводит демонстрацию и объясняет ограничения. Не нужно заявлять
самостоятельное ручное написание всего кода.
