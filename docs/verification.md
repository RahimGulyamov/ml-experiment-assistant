## Найденные проблемы и исправления

1. **Равные лучшие метрики.** На реальном Iris три конфигурации получили accuracy=1.0,
   но UI сначала отмечал только одну. Теперь все равные значения выделяются;
   отчёт явно перечисляет tied_best_ids. Это не означает статистического равенства.
2. **Наследуемое свойство вместо метрики.** Запрос `metric=toString` мог попасть
   в сравнение через Object.prototype. Используется Object.hasOwn; добавлен тест.
3. **Ошибочная уверенность в ключе.** Ввод ключа показывал «LLM подключена» без
   реального запроса. Заменено на «Ключ задан», в форме объяснён момент проверки.
4. **Смешение разных выборок.** Группировка и MCP блокируют сравнение разных
   experiment/dataset/split. Добавлен отрицательный сценарий со split=test.
5. **Старый ответ после смены данных.** При изменении набора, метрики или выбора
   запрос отменяется, результат очищается. Экспорт не получает старый вывод с новыми ID.
6. **Скрытые пропуски и failed.** Они не становятся нулём и не участвуют в рейтинге;
   инструмент возвращает причину исключения. При нулевом baseline нет Infinity.
7. **Заголовки CSV.** Papa Parse переименовывает дубликаты автоматически. Импорт
   отклоняет такой файл, чтобы не потерять данные незаметно. Warning библиотеки
   в соответствующем тесте ожидаем и не является падением.
8. **Утечка через ошибки провайдера.** Ответы провайдера не выдаются наружу целиком:
   показывается безопасное сообщение по HTTP-коду, без тела, которое может отражать секрет.
9. **Неограниченные входы/цикл.** Добавлены потоковый лимит HTTP-тела, строгая схема,
   ограничение количества запусков/историй, deadline, максимум раундов и tool calls.
10. **Нерелевантный шаблон.** Неиспользуемые UI-компоненты и DB-примеры стартера
    проверены побайтово и убраны с резервной копией; зависимости сокращены с 772 до 313.
11. **Мобильное переполнение.** На ширине 390 px кнопка настроек выходила вправо
    на 4 px. На узком экране верхняя навигация скрыта; ссылки остаются внизу.
12. **Демонстрация только на искусственных числах.** Добавлены реальные замеры
    обучения Iris и воспроизводимый скрипт с проверкой checksum исходных данных.

13. **Конфигурация в системном контексте.** Имя метрики проходит ту же проверку
    идентификатора в API и MCP, что и ключи импортируемых метрик. Переносы строк
    и инструкции в этом поле отклоняются до обращения к модели.
14. **Уязвимые зависимости шаблона.** Обновлены Next.js и Zod, зафиксированы
    исправленные транзитивные зависимости. Совместимость Zod с MCP подтверждена
    повторными тестами и сборкой.

Часть защит заложена при реализации; отдельное ревью подтвердило их тестами.
Не все пункты списка являются дефектами, обнаруженными только после первого build.

## Что ещё не подтверждено

- **Веб LLM API и UI launcher.** Реальная LLM проверена через локальный Codex +
  stdio MCP. Web Chat Completions API без отдельного ключа и интерфейс конкретного
  корпоративного launcher этим тестом не подтверждены. Управление нативным launcher
  из текущей сессии недоступно из-за разрешений Computer Use.
- **Преподавательский доступ и воркшоп.** Участие автора и согласование с курсом
  нельзя выполнить кодом. Сайт должен открываться у преподавателя.
- **Нагрузочная эксплуатация.** Нет distributed rate limiting, аккаунтов и БД;
  приложение рассчитано на учебную нагрузку.
- **Галлюцинации.** Ограничение tools не гарантирует истинность финального текста.
  Ответ нужно сверять с журналом и проводить ручные eval на реальной модели.
- **Качество статистики.** Для Training нет оценки значимости; один seed и маленькая
  validation не доказывают преимущество. A/B сохраняет входные CI, но не пересчитывает
  их по средним и не подтверждает метод исходного отчёта.
- **Корпоративные API.** Формат скалярных выгрузок поддержан; сетевые коннекторы
  Training/A/B не подключены без подтверждённых контрактов и прав.

## Дополнительная проверка веб-чата перед сдачей

1. Подключить свой ключ и модель с tool calling, не показывать ключ на записи.
2. Вопрос: «Сравни выбранные запуски по accuracy и времени».
   Ожидание: MCP-сравнение, реальные ID/числа, оговорка о компромиссе и seed.
3. Вопрос о run-004. Ожидание: история/diagnose_run и эвристический характер сигнала.
4. Вопрос о следующем эксперименте. Ожидание: гипотеза и фиксируемые параметры,
   без выдуманных результатов.
5. Проверить, что провайдерская ошибка не превращается в расчётный ответ под видом LLM.
6. Записать модель, дату и вывод ручной проверки; только после этого отметить
   полный LLM-сценарий как проверенный.

## Расширение Training/A/B и реальная LLM

Локальный авторизованный Codex выполнил три **завершённых** вызова реального stdio
MCP: list_workspace_sources, compare_training_exports, analyze_ab_result. Ошибок
MCP и выполнения shell в проверке нет. Контрольные ответы: общий шаг 200,
quality delta=0.04, A/B guardrail_violation с negative_feedback. Все входы
искусственные. [Отобранный публичный протокол](verification-real-llm.json).
Точный ID модели не присутствует в JSON-событиях CLI; использован default клиента.
Это одна успешная контрольная проверка, не оценка качества на широком наборе задач.

Дополнительно SDK-тесты запускают stdio процесс, проверяют Training/A/B и явный
workspace без примешивания demo runs. Негативные случаи покрывают дубликаты шагов,
разные протоколы, неполный общий шаг, ДИ через ноль, нулевой control, обратный период
и совпадающие группы. Отдельно проверяются временные границы с timezone и отбор
данных при экспорте.

Браузером загружены два искусственных scalar JSON. До подтверждения одинакового
протокола сравнение заблокировано; после подтверждения получен шаг 200 и delta=.04.
Выбор только val/quality отражён в скачанном workspace: оба экспорта имеют локальные
псевдонимы, val/loss и время t отсутствуют, ab=[]; файл проверен после скачивания.
В A/B видны промежуточный период, единицы ДИ, роли/направления и ухудшенный guardrail.
Десктопная проверка выполнена на ширине 1280. Запрошенный viewport 390 в текущем IAB
не применился (DOM остался 1280); новую страницу на 390 эта сессия не подтвердила.
Предыдущая мобильная проверка основного интерфейса приведена выше.

При ревью расширения исправлены:

- Экспорт сначала мог смешивать соседнюю вкладку с выбранными данными. Теперь
  сохраняется только открытая вкладка и выбранные серии; время t исключено по умолчанию.
- Порядок нажатия checkbox мог менять baseline только в UI. Сравнение и скачивание
  теперь используют один порядок источников.
- Общая подпись происхождения могла пометить demo A/B как загруженный файл.
  Происхождение Training и A/B отслеживается отдельно.
- Относительный ДИ при control=0 мог дать ложный направленный сигнал. Теперь
  результат inconclusive с объяснением.
- Сравнение дат строками некорректно для разных timezone. Проверяются фактические
  моменты времени, исходные строки сохраняются.
- Подсказка модели предлагала оба вида анализа для файла с одной вкладкой.
  Теперь запрос соответствует выбранному типу данных.

Публичные fixtures, документация и проверочный ответ не содержат частных endpoint,
идентификаторов или результатов экспериментов компании. Интерфейс launcher,
корпоративная маршрутизация модели и живые сетевые API не объявлены проверенными.

Размер workspace проверяется по фактической форматированной JSON-выгрузке:
проверка только компактного JSON могла пропустить файл, который после добавления
отступов превышал бы 2 MiB и отклонялся stdio-сервером. Граница закреплена тестом.
Обе спецификации OpenSpec проходят строгую валидацию: 2 passed, 0 failed.
