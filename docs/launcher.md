# Локальный AI-клиент и MCP

Существующая подписка ChatGPT/Codex может использоваться в авторизованном локальном
Codex-клиенте. Она не является API-ключом для публичного веб-сервиса. Веб-чат
Run Notes по-прежнему использует отдельный ключ OpenAI/OpenRouter. Токены входа
ChatGPT и корпоративного launcher нельзя вставлять в поле API-ключа сайта.

Корпоративный launcher управляет запуском поддерживаемых AI-клиентов и набором
инструментов. Наличие произвольного HTTP LLM API из этого не следует. Совместимый
путь для Run Notes — локальный stdio MCP, подключённый к клиенту, который владелец
запускает разрешённым в организации способом.

## Начать на искусственных данных

```sh
npm ci
npm run launcher:config -- --codex
```

Команда печатает секцию `[mcp_servers.run_notes]` с абсолютными путями текущего
checkout. Для клиента с JSON-конфигурацией MCP:

```sh
npm run launcher:config
```

Это конфигурационные фрагменты, не команда автоматического изменения глобальных
настроек. Добавьте их поддерживаемым способом в настройку своего клиента. Launcher
может управлять этими настройками централизованно — тогда используйте корпоративный
каталог или установленную процедуру регистрации локального сервера. Автоматическая
регистрация в конкретном launcher этим проектом не проверена.

После подключения спросите клиента:

> Используй MCP run_notes. Сначала list_workspace_sources. Сравни training-a и
> training-b по val/quality и val/loss на полном общем шаге. Затем разбери ab-demo:
> проверь guardrails, единицы ДИ, период, срез и промежуточный статус. Объясни
> ограничения и не выполняй никаких раскаток или изменений внешних систем.

Ожидаемые проверяемые факты: общий шаг 200, разница quality=0.04, нарушение
negative_feedback guardrail. Это искусственные контрольные примеры.

## Импорт своих разрешённых выгрузок

1. Откройте `/developer` в Run Notes. Для внутренних данных используйте копию
   приложения в разрешённом контуре; публичная версия предназначена для
   искусственных или отдельно разрешённых данных.
2. Training: экспортируйте скалярные ряды в JSON без preview и сглаживания, по Step.
   Поддерживается массив `{name, points: [{s, t, v}]}`. Загрузите файлы, подтвердите
   одинаковые датасет/протокол, выберите только разрешённые метрики.
3. A/B: импортируйте портативный агрегированный отчёт по шаблону. Система не
   утверждает совместимость с неизвестной выгрузкой внутреннего сервиса без адаптера.
4. Скачайте workspace открытой вкладки. Имена файлов и служебные run ID Training
   не переносятся; экспорты получают локальные псевдонимы. Время t по умолчанию
   исключено. Метки и значения выбранных метрик остаются — проверьте их допустимость.
5. Создайте конфигурацию сервера с явно выбранным файлом:

```sh
npm run launcher:config -- --workspace /absolute/path/run-notes-workspace.json --codex
```

Локальный сервер читает только этот файл, проверяет схему и лимит 2 MiB. У модели
нет инструмента для произвольных путей, shell, изменения экспериментов, запуска
обучения, сетевых запросов в корпоративные сервисы или чтения токенов. Полный
контекст MCP получает AI-клиент с его правилами маршрутизации и хранения.

## Инструменты

| Инструмент | Что проверяет |
| --- | --- |
| `list_workspace_sources` | Источники, протоколы, серии, группы, период и срез A/B |
| `compare_training_exports` | Один полный общий шаг всех выбранных серий; без интерполяции |
| `read_scalar_window` | До 200 точных точек выбранной серии |
| `analyze_ab_result` | Эффект, направление, входной ДИ, guardrails и ограничения |

Старые инструменты анализа запусков доступны в demo-режиме. При `--workspace`
сервер не примешивает демонстрационные запуски к пользовательским данным.

## Реальная LLM-проверка

```sh
node scripts/verify-real-llm.mjs
```

Нужен установленный и авторизованный Codex CLI. Можно задать путь через
`RUN_NOTES_CODEX`. Проверка использует только искусственные fixtures, временный
пустой каталог, ephemeral-сессию, read-only sandbox и процессную конфигурацию
одного MCP. Глобальная конфигурация не меняется. Это локальная ручная проверка,
не способ публиковать исполнение Codex с личной авторизацией на публичном сервере.

Итог проверяется по завершённым MCP-вызовам и числам ответа. Логи остаются в
игнорируемом `work/real-llm`. Для публичного протокола отбираются только факты теста.
[Подтверждённый результат](verification-real-llm.json). Проверка интерфейса
корпоративного launcher и web Chat Completions API в этот результат не входят.

## Дальнейшее корпоративное внедрение

Нужны отдельно подтверждённые контракты и доступы для read-only адаптеров Training
и A/B, развёртывание в разрешённом контуре, авторизация пользователей, ограничения
доступа к источникам, аудит и эксплуатационные лимиты. Текущий MVP не заменяет эти
меры. В публичном репозитории нет внутренних endpoint, идентификаторов, токенов,
результатов корпоративных экспериментов или копий внутренней документации.

Официальные сведения: [Codex authentication](https://learn.chatgpt.com/docs/auth),
[MCP configuration](https://learn.chatgpt.com/docs/extend/mcp?surface=cli),
[non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode).
